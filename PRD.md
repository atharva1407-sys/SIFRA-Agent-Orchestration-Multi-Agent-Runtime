# Product Requirements Document (PRD)

## 1. Project Overview
**Product Name:** SIFRA — Agent Orchestration & Multi-Agent Runtime
**Description:** SIFRA is a robust, full-stack application designed to provide the infrastructure layer—the "harness"—around Large Language Models (LLMs). It moves beyond basic API wrappers to offer a durable, isolated, memory-aware, and highly observable environment for running complex autonomous agent systems.

## 2. Problem Statement
Raw LLM APIs lack the built-in infrastructure necessary to build reliable, long-running agentic workflows. Developers face challenges with:
- **Fragility:** Agent loops fail completely on unexpected crashes or API rate limits.
- **Context Limits:** Models "forget" information over long tasks as token limits are reached.
- **Security:** Giving models the ability to execute code introduces severe system vulnerabilities.
- **Observability:** It is difficult to track an agent's internal "thought process" and tool usage in real-time.

SIFRA solves these issues by acting as intelligent middleware that manages state, memory, security, and UI observability.

## 3. Target Audience
- **AI Engineers & Full-Stack Developers:** Building production-ready, reliable AI agent systems.
- **AI Researchers:** Experimenting with multi-agent orchestration and advanced memory architectures.

## 4. Key Features & Functional Requirements

### 4.1 The Agent Harness (Middleware)
- **Requirement:** The system must act as an intermediary between the user input and the LLM.
- **Capabilities:** Must seamlessly inject system prompts, tool definitions, and guardrails to guide the LLM's execution loop (receive → think → act → respond).

### 4.2 Durable Execution (State Management)
- **Requirement:** The system must checkpoint the agent's progress continuously.
- **Capabilities:**
  - Persist conversation state and tool execution states to a PostgreSQL database.
  - Automatically resume execution from the last successful checkpoint in the event of a crash, network failure, or API rate limit, bringing recovery time under 2 seconds.

### 4.3 Advanced Memory Hydration
- **Requirement:** The system must manage the LLM context window efficiently to allow for extended task execution (e.g., 10x beyond native context limits).
- **Capabilities:**
  - Implement a sliding window of recent conversational turns.
  - Automatically summarize older context when token thresholds are reached.
  - Maintain critical pinned state (e.g., core objective, system instructions) that is never summarized away.

### 4.4 Secure Code Sandboxing
- **Requirement:** The system must safely execute untrusted code generated by the LLM.
- **Capabilities:**
  - Execute code within an isolated Node.js `vm` environment.
  - Restrict access to the underlying host file system and critical Node.js globals.
  - Enforce strict runtime constraints (e.g., 2-second timeout limits) to kill synchronous infinite loops and runaway processes.

### 4.5 Real-Time Dual-Pane Workspace (UI)
- **Requirement:** The frontend must provide real-time interaction and deep observability.
- **Capabilities:**
  - **Interaction Pane:** A user-friendly chat interface for task delegation.
  - **Event-Stream Pane:** A live, WebSocket-powered log showing internal agent events, tool usage, and reasoning steps with sub-50ms latency.
  - **Dynamic UI:** Include a collapsible sidebar, context-aware auto-renaming for chat sessions, custom loading micro-animations, and light/dark theme toggling.

## 5. Technical Architecture & Stack

### 5.1 Architecture Diagram
- **Frontend:** React + Vite
- **Communication:** WebSockets (Events & Commands)
- **Backend Node:** Express + Node.js
- **Database:** PostgreSQL (via Drizzle ORM) for Durable Execution
- **LLM Engine:** OpenAI / Vercel AI SDK

### 5.2 Tech Stack Details
- **Languages:** TypeScript, JavaScript, HTML, CSS.
- **Backend:** Node.js (run with `tsx`), Express, `ws` (WebSockets).
- **Frontend:** React, Vite, Tailwind CSS, Lucide Icons, shadcn/ui.
- **Database / ORM:** PostgreSQL, Drizzle ORM.
- **AI Integrations:** Vercel AI SDK, OpenAI API.

## 6. Non-Functional Requirements (NFRs)
- **Performance:** WebSocket latency must remain under 50ms for live event streaming. The application should support monitoring of multiple concurrent agent sessions.
- **Reliability:** The system must guarantee that no progress is lost if the backend server crashes midway through an agent's multi-step tool execution.
- **Security:** Agent-generated code must not be able to compromise the host machine or access environment variables (like the OpenAI API key).
- **Usability:** The UI must follow modern glassmorphism design principles and provide immediate visual feedback (e.g., "ThinkingDots") when the LLM is processing.

## 7. Future Scope / Roadmap
- **Multi-Agent Routing:** Enabling a "supervisor" agent to route sub-tasks to specialized worker agents.
- **Cloud-Hosted Sandboxing:** Migrating from the local Node.js `vm` to a true microVM sandbox (e.g., Firecracker/e2b) for full remote execution security.
- **Extended Tool Libraries:** Pre-built integrations for GitHub, Notion, and terminal access.
